# knowledge-companion

## 适用场景

在以下场景触发：

- 需要沉淀一段新知识
- 需要从一段来源材料批量生成知识卡片
- 需要补充或修正已有知识
- 需要检查知识库质量问题
- 需要建立两条知识之间的关系
- 需要根据问题自动检索相关知识并给出中文回答
- 需要查看当前分类体系

## 四层结构

当前知识库按四层结构组织：

1. 来源层：记录原始材料的标题、来源类型、地址和元信息。
2. 知识域层：记录业务知识、项目知识、测试方法、排障案例等分类。
3. 知识卡片层：记录可被检索和问答使用的最小知识单元。
4. 证据与关系层：记录来源片段、标签，以及知识之间的补充、依赖、冲突、重复等关系。

## 输入类型

### 1. 知识写入

适合输入：

- 一段排障结论
- 一个项目背景摘要
- 一套测试方法
- 某个平台工具的使用要点
- 某个仓库模块的理解说明

处理规则：

1. 先提炼标题、摘要、正文。
2. 自动判断主分类。
3. 自动补齐标签。
4. 调用知识服务的 `add_knowledge` 或 `update_knowledge`。

### 2. 来源导入

适合输入：

- 一段会议纪要
- 一段排障记录
- 一段项目说明
- 一段接口联调记录

处理规则：

1. 优先保留来源标题、来源类型、来源地址和来源所有者。
2. 调用 `ingest_source` 创建来源记录。
3. 如果内容有多个自然段，默认按自然段拆成多张知识卡片。
4. 每张知识卡片都要关联对应证据片段，方便后续追溯。

### 3. 知识质检

适合输入：

- “检查知识库质量”
- “看看哪些知识缺来源”
- “扫一下有没有摘要或正文过短的问题”

处理规则：

1. 调用 `lint_knowledge`。
2. 优先解释 error，再解释 warning。
3. 输出时说明问题类型、影响和建议补充内容。

### 4. 知识关联

适合输入：

- “把知识 1 和知识 2 关联起来”
- “这两条知识是补充关系”
- “这两条知识存在冲突”

处理规则：

1. 明确起点知识、终点知识和关系类型。
2. 调用 `link_knowledge`。
3. 关系类型优先使用 related、depends_on、duplicates、conflicts、supersedes、supplements。

### 5. 提问检索

适合输入：

- “导量空结果先排查什么？”
- “接手新项目先看哪些信息？”
- “某个策略测试重点有哪些？”

处理规则：

1. 先判断问题更偏向哪个知识域。
2. 先调用 `search_knowledge` 做轻量召回，只看标题、摘要、分类、标签、来源标题和证据数量。
3. 优先基于摘要判断最相关候选，避免一次展开多条正文。
4. 只有摘要不足以回答时，才调用 `get_knowledge(item_id)` 读取单条详情。
5. 需要直接生成答案时，可调用 `ask_knowledge`，但仍应优先使用返回的摘要候选，不拼接多条全文。
6. 输出时按“结论、依据、下一步建议”组织回答。

## 回答风格

- 优先中文
- 先给结论，再给依据
- 先摘要后详情，避免全量遍历知识库内容
- 风格偏“熟悉业务的同事”，不要只罗列原文
- 如果知识不足，要明确说明缺口，并建议补充什么内容
